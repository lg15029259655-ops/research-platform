# 开发与精读经验记录

2026-10-06

- 截图中的 API 凭证即使 OCR 结果一致，也不能视为已验证。必须用真实请求核对鉴权；失败时保留错误状态，不展示模拟答案，也不推进阅读位置。
- 阅读进度应由后端保存的章节单元 ID 控制。模型输出只负责讲解，不能通过分析其回复来猜测当前章节。
- Figure 讲解必须把 PDF 原页图像和图注一同送入视觉模型。矢量图可能没有可提取的嵌入图片，页面渲染是必要后备路径。
- 按标题规则解析医学 PDF 只能得到初步结构。扫描版、双栏和特殊排版需要明确提示阅读者核对原文，不能补造缺失章节。
- 前端开发服务与生产构建会共用 `.next`，检查构建时应先停止开发服务，构建结束后再启动。
- 后续优化精读写作时，优先讲清科学问题、核心比较和证据边界，避免把每个单元都写成固定套路的“背景—方法—结果”摘要。

2026-10-07

- 用户明确指出任务范围是完整比赛展示版，不应只回答最后一句“有问题吗”。后续要把跨轮需求合并执行，再报告实际实现与验证结果。
- 前端自报 UUID 只能起到便利分组作用，不能保证多用户隔离。匿名身份应由后端签发随机凭证，以 HttpOnly 持久 Cookie 保存，并在每个论文入口校验 owner。
- 正常关浏览器后的恢复依赖持久 Cookie 和 SQLite；`localhost` 与 `127.0.0.1` 的 Cookie 不共用，文档和启动地址必须保持一致。
- Results 不能预设每篇文章都有 Figure。按 Figure、Table、结果正文逐级兜底，避免跳过临床或表格为主的论文。
- `visual_verified` 只能在图像真正进入视觉请求且回复成功后设为真。视觉失败要清除不完整流式内容，改用文字解释并明确标注，不把普通文本调用包装为视觉解析。
- UI 测试发现开发服务的动态 PDF 组件在构建并行时可能发生 ChunkLoadError；构建前应停开发服务，完成后重启并重新加载页面。
- 用合成图像测试可验证页面映射和视觉调用链，但不能证明真实论文版面解析准确；后续需用多篇不同类型论文验证。
- PDF 页数不能只依赖阅读组件回调；后端解析页数可作为稳定兜底。采用 pnpm 时，直接引用 `pdfjs-dist` worker 也应把它列为前端直接依赖，避免开发模式下解析失败。
- 模型输出会带 Markdown 表格与列表，直接按纯文本显示会明显降低可读性。使用标准 Markdown 渲染，同时保持来源约束，不能让排版掩盖证据不足。
# 本轮跨学科扩展经验

- 先区分检索记录与已解析全文，再决定哪些 AI 功能可开放。只有元数据时不能展示 PDF 跳页、Figure 视觉核验或全文对比。
- OpenAlex 给出的 `pdf_url` 是线索，不保证返回 PDF。下载前限制公开 HTTPS 地址，下载后核对 `%PDF-` 文件头；失败时保留元数据并提供手动上传。
- 结构化任务不能仅依赖“请返回 JSON”。应使用 Pydantic 验证、必要时重试，并核对引用的 paper_id、unit_id 是否属于当前用户及论文。
- 跨学科模板不能把动物模型、实验组、Figure 当作所有领域的固定字段。保留既有医学能力的同时，用领域判断调整解释角度，并提供通用兜底。
- 研究设计模型容易给出没有依据的样本量、阈值或成本百分比。提示词需限制，界面需说明是待核验方案；成本调整需展示具体变化与代价。
- 真实 PDF 的版权声明可能排在标题之前。标题应结合字体和位置选择，不能简单取首页首个长句；参考文献后的 Figure 不应被当作主文结果。
- 即使要求“只依据当前单元”，模型也会凭熟悉的论文题目补出外部知识。标题单元需使用独立的极短任务约束，不把全文历史或领域推断放进标题上下文。
- Figure 优先不能等同于 Figure 独占 Results。遇到同篇同时有 Figure、Table 与无图结果段落，应全部保留为独立单元，让用户按证据类型阅读。
- 第三方文献 API 的匿名额度耗尽与接口实现故障需区分。保留已验证的本地模块与测试结果，给出清楚的 429 提示，额度刷新后再复验实时检索。
- 状态文案要对应数据库事实：元数据、PDF 正在解析、PDF 解析失败各有不同提示，不能统称为“只有摘要”。
- 旧 AI 回复不应无条件进入下一章节上下文。跨章节依靠 PDF 原文和阅读单元状态；同一单元的追问才复用该单元的历史，防止早期错误污染后续讲解。

## 本轮产品化复盘

- 用户要的是连续完成整条比赛演示链，而不是单独讲每一页的方案。跨页面状态应保存在 owner 作用域内的 Workspace，只保存论文和研究结果引用，避免复制全文。
- 图谱、X-Ray、证据地图、研究空白和沙盘应先展示结构，再按节点展开解释。页面上默认铺满摘要或 AI 长文会掩盖科研关系；压缩图谱侧栏摘要后更易读。
- OpenAlex 缓存必须写入真实成功返回的结果、模式、页码和时间。缓存命中与过期回退要在界面区分；不得把 fixture 当作比赛现场的真实文献。
- SQLite 读取带时区时间字段时可能丢失时区信息；对外的抓取时间应统一补 UTC，否则新结果与缓存结果时间格式不一致。
- 保存 JSON 时不能截断序列化字符串，否则下一次读取会因无效 JSON 崩溃。超过长度应明确拒绝或按数据结构裁剪。
- 沙盘回退后再编辑会形成轻量分支；新版本的父节点应是当前恢复的版本，版本编号仍单调增加。
- 本轮浏览器测试期间用户也在操作本地页面，不能把其页面内容当作自己的测试数据。真实 API 端到端测试使用独立匿名会话，结束后清理测试论文与用户，保留公开检索缓存。
- 恢复 AI 结果不能简单取“最近一条”：如果用户从研究空白切换了研究问题，旧 Novelty 或综合图会看似属于新主题。应由 Workspace 保存 artifact ID，并校验结果的主题或论文集合。对比篮变化要使旧综合引用失效。
- Evidence Map 空数据不是成功视觉化。模型可能给出合法但空的 `controversies`；界面应明确呈现“证据不足”，并引导核对矩阵和原文，而非留三列空白或杜撰命题。
- 工作流“自动带入”不能只把文本填进下一页输入框。真正生成设计时也必须把研究空白、共识、争议和论文证据范围放入模型上下文；否则界面看似连续，模型仍按孤立问题随意建议实验对象。

## 界面验收复盘（2026-10-07）

- 四个一级入口是产品骨架，应在所有页面保持同一位置、同一尺寸和清晰的当前状态；不要在顶部、工作区和侧栏重复渲染三套导航。
- 表格单元格的“展开”必须增加信息价值。预览用于快速扫读，详情应提供证据边界、来源状态和打开原文的路径，不能把同一段文字放大重念。
- 交互图不能仅凭静态截图验收。要实际点放大、切换中心、拖动画布，并检查缩放数值和节点位置是否变化；强制布局停止后反复自动适配会制造跳动。
- 长文案放在抽屉或折叠面板，画布节点只写可扫读的标题。保留完整说明的入口，避免为“简洁”牺牲信息可达性。
- 当结构化 AI 结果没有可核验命题时，应把缺失当成明确的数据状态展示，说明不能据此判断支持或冲突；不要用三个空白栏制造分析完成的错觉。
- 相似性图若只有高、中、低分层，就用清楚、不重叠的分层布局；不要画看似精确的二维距离。视觉设计应与证据精度一致。
- 恢复页面时要等相关 artifact 读取完成后再决定显示哪个标签页。先加载设计版本、后加载新颖性结果时，过早切页会让已经保存的分析在刷新后看似消失。

## 阅读与可视化复盘（2026-10-08）

- “精读是演示重点”不能说成“精读是首页”。四个一级入口仍是首页结构；讲解时要区分产品首页和演示主线。
- 用户按“开始精读”预期立刻得到有实质内容的起读分析。题目和摘要可以合并为首次合理阅读单元，同时保留独立的 Manifest 单元，进度落在摘要，下一次进入引言。
- 阅读布局应优先照顾长篇 AI 讲解的可读性。默认给讲解更多宽度，PDF 按容器适宽；流式生成时及时展示选中的单元，避免状态栏还显示上一节。
- 研究设计图上的连接文案容易与节点重叠。画布只保留结构与短标题，连接逻辑放在节点详情；研究空白也应先给一条主线，再按需展开备选内容。
- 相似性空间图只能表达定性分层。轻量浮动和景深可改善视觉感受，但圈层需明确标注高、中、低，不能用装饰性的空间位置暗示精确向量距离。
- 本地 `next start` 和 `uvicorn` 是常驻进程。重新构建或改后端代码后需重启并检查端口，不能仅凭构建成功就宣称浏览器已加载新版。
- 一些期刊首页有摘要段落却不印 “Abstract” 小标题。只按标题分段会让首次精读退回标题；对这类文章可用首页长段落末尾的 DOI 引用作保守识别，并只补入可信的摘要，保留已有消息和单元 ID。
- 演示流程要检查“离开后再回来”。保留检索词却清空结果，会让用户误以为检索失效；优先从已有缓存恢复，避免为了恢复界面再次消耗外部 API 配额。
- 长篇精读记录恢复时，应定位到最近一条助手回复的开头，便于从头读；流式生成时才跟随底部，且用户主动上滚后不要强制拉回。
- 已生成的文献综合应先展示结果，把重新选论文收进明确入口；精读页论文库也应能收起，让 PDF 和讲解内容按任务需要获得空间。
- 文献关系图的核心任务是快速辨认“哪篇论文、与中心是什么关系、下一步能做什么”。只有圆点和连线会把识别成本转嫁给用户；标注标题、年份、关系类型的稳定布局更适合演示与扫描。
- 力导向动画、自动适配画布和持续浮动会叠加造成“点了以后卡住”的感觉。先消除不必要的模拟和循环动画，再为真正耗时的网络或 AI 请求提供即时、可见的处理中状态。
- 首次进入页面的空白区应给操作路径与可点击示例，但示例必须明确只是引导，不能充当已经生成的证据或分析结果。

## 工作台视觉与流程复盘（2026-10-08）

- 每张卡片都使用同一浅绿色、阴影和按钮，会让信息失去主次。科研工作台更需要稳固的字级、留白、少量强调色，以及每个对象清楚的一到两个主要操作。
- 四阶段导航要同时回答“我在哪里”和“下一步需要什么”。仅列四个入口不够；工作区应显示当前主题、待综合数量和下一阶段前提。
- 次要操作可以折叠，但必须保留可发现入口。检索论文卡优先给“浏览关系”和“取得全文精读”，保存、加入对比和设为中心放入展开区。
- 修改论文选择时，不应立刻清空已经生成的综合分析。保留旧结果并显著标明它属于上一次选择；新结果生成后再替换。不同研究主题则应清除旧结果引用，避免跨题误用。
- 站内步骤跳转应使用客户端路由，避免整页刷新造成等待感。网络、PDF 解析和 AI 本身的耗时仍需阶段化状态提示，不能靠动画掩饰。
- 验收不仅看桌面截图；移动端标题是否断成孤字、卡片按钮是否拥挤、展开交互是否能触发，都应通过实际浏览器检查。
- 用户说“恢复原来的样子”时，应保留原有图形语法，只修复具体缺点。文献关系原本是中心气泡加周围气泡，改成卡片布局会改变用户认可的方向；确认后恢复放射结构，优先稳定位置、缩放和平移。
- 可视化组件不能只通过构建验收。第一次引入 Canvas 力导向图时，自动适配把气泡放大到互相遮挡；真实截图及时暴露了问题。图形的首屏比例、点击、移动端触控都需实际检验。
- 真 3D 行星图适合展示高、中、低的定性层级，但轨道位置不能暗示精确相似度。提供同一组论文的可读列表和文字证据范围，保证图形交互以外仍能核对文献。
- 图上写“可拖动”要分清拖动画布和拖动节点。用户说气泡不能动时，问题是节点本身无法移动；应给节点单独的指针拖动状态，并让连线随节点坐标更新，再用浏览器自动化核对拖前拖后的坐标。
- 3D 图设为按需渲染后，静止画面容易被理解为“动不了了”。对需要持续运动的场景，用轻量、低速的帧循环；手动旋转时暂停场景公转，提供显式暂停按钮，同时限制像素比和几何复杂度。
- 视觉冲击力需要焦点和对比，而不是全站铺满渐变。只让关系图和行星图进入深色舞台，周围科研工作台仍保持明亮，能让图形成为明确的视觉中心。

## 三维图谱与论文对比复盘（2026-10-09）

- 用户要的是可旋转的真实三维空间和能单独拖动的文献节点，两种交互都必须在浏览器中实际验证。单纯把 SVG 球体画得立体，无法满足要求。
- 中心论文与周围气泡的既有图形语法应保留；改变渲染技术时，仍要让用户一眼认出中心、相关研究和参考文献，并提供文字选择入口。
- 三维画布在窄屏上会因视锥宽度不足裁掉外围节点；摄像机距离应随容器宽度调整，不能只检查桌面截图。
- 某些 3D 的 DOM 标签在画布卸载或重置时可能触发节点移除错误。装饰性标签若已有图例和标题承担信息功能，可以从 Canvas 中移除，避免卸载冲突。
- 论文综合不宜把所有维度的长文本同时摊成表格。一次聚焦一个维度，每篇论文只显示短预览；完整内容和来源在详情抽屉中保持可达。
- AI 综合文本里出现原始论文 UUID 会破坏可读性。显示层可把已知 ID 映射到与对比卡一致的论文编号，原始来源标记留在详情中供核对。
- 自动冒烟检查要随组件交互模型一起更新。SVG 的坐标检查不能继续用来验收 Canvas；改为验证画布、选择反馈、重置和移动端宽度，再用浏览器手动验证节点拖动与视角旋转。

## 部署沟通复盘（2026-10-09）

- 用户提到已有服务器或此前部署时，先查同机项目的部署文档、域名、服务配置和线上健康状态，再询问真正缺失的主机信息；不应先把已有记录让用户重复截图。
- 2026-10-12 再次误把早期部署模板当成当前状态。论文平台已在阿里云香港 ECS 的 `lunyu-lab.site` 上线；校园雷达在另一台腾讯云中国内地服务器。以后先核对最近一次实际部署记录，再看模板，并明确区分本地项目与线上环境。
- 首页改动曾只在本地生效，却让用户以为线上已更新。今后说明“源码完成”“本地构建通过”“线上发布完成”三个独立状态；发布后检查公网页面的新版标志和后端健康接口。
- 线上前端使用 Next.js standalone 发布目录和 `research-platform-frontend.service`，源码文件不能直接覆盖到线上生效。手动发布应先在临时目录构建，再创建新 release、切换 `current` 并保留旧 release 以便回退。
- 用户明确不希望反复出现输入弹框；需要其在 Workbench 操作时，直接在聊天中给完整、可复制的命令，并等待终端结果。
- 对 2 核 2 GB 的测试服务器，要区分“少量用户可试运行”和“多人长期公开服务”。先隔离服务和数据、限制并发、实测 PDF 解析内存峰值，失败后再决定升级。
- 新域名在中国内地旧服务器共用部署时仍需新增网站备案。域名命名审核、实名认证与备案是不同状态；生产配置可以先准备，但不能把未备案域名公开接入。

## 线上精读故障复盘（2026-10-12）

- PDF 首页的出版商页眉（如 `HHS Public Access`）可能被误认成论文标题。解析质量要以正文、章节和题目共同判断，不能只看状态为 `parsed`；修复解析规则后，旧论文仍需明确提供重新识别入口。
- 文献综合中的空栏应显示“当前证据不足”的明确状态，并在开始综合前拦住未可靠提取正文的 PDF，避免把坏输入包装成完整结果。
- 用户感觉“所有页面都卡”时，分别测浏览器渲染、模型请求和客户端到服务器的网络连接。若大陆直连香港主机超时，前端微调无法解决首次打开慢的问题；应把源码修复与线上访问状态分别报告。
- 比赛用途说明应准确描述项目及 AI 结果的限制，首次展示后不重复打扰；不能暗示这一说明能替代备案或通过审核。
